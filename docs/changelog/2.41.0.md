# Changelog — v2.41.0

## Summary

A conversational assistant for Telegram, and the dependency upgrade that made
it possible. Team members now log their time by describing their day in their
own words, and ask about their own Jira work in Persian, instead of stepping
through a fixed button flow.

## Features

### Free-text time logging
- A message such as «امروز ۵ ساعت برای پارسچت وقت گذاشتم که ۳ ساعتش برای
  درگاه بانک بود» is parsed into one worklog per piece of work, matched
  against the sender's own open issues.
- The model returns candidate **indices**, never issue keys, so it cannot
  invent a key and write a worklog to an issue that does not exist.
- Arithmetic is checked in Python: a breakdown that does not add up to the
  stated total is surfaced rather than trusted.
- Ambiguity becomes a tappable question with at most four options and a skip;
  a skipped entry is dropped rather than logged somewhere wrong.
- Backdating: «۲ روز پیش» resolves against a date passed in from Python, and
  a date landing in the future is discarded — Jira accepts one silently and
  it is always wrong.
- `ریموت` and `اضافه‌کاری` are preserved verbatim in the worklog comment,
  because they carry payroll meaning for this team.
- Ordinal references («تسک اول»، «دومی»، «آخری») are resolved in Python
  against the list the bot last printed, not left to the model.

### Task assistant (LangGraph)
- `TaskAssistantAgent` answers questions about a person's own Jira work using
  six scoped tools: `board_link`, `task_details`, `list_tasks`, `count_tasks`,
  `logged_hours`, `whoami`.
- Identity is bound in `AssistantContext` at call time and authorisation is
  decided in Python, so no prompt can talk the assistant into reading someone
  else's work.
- `task_details` inherits context from the parent Story and Epic when a
  Sub-task carries no description of its own, and lists `blocks` /
  `is blocked by` relations and attachments.
- `list_tasks` filters by project, status, issue type, active sprint and
  deadline; sub-tasks render nested under the work they belong to.
- Answers cite issue keys as links, rendered as Telegram HTML.

### Message routing and memory
- Every free-text message is classified as `worklog`, `question` or
  `chitchat` before anything else happens, on `gpt-4.1-nano` at temperature 0.
- Classification fails closed: an unrecognised label, an empty message or a
  failed call all resolve to `chitchat`, because doing nothing is safer than
  logging time nobody asked to log.
- The last six turns are remembered per chat, so «فقط همین دوتاست؟» is
  answered as the follow-up it is.

### Entity aliases
- `scripts/seed_entity_aliases.py` maps how the team speaks onto Jira
  identifiers — «آواخرد» to `FOLLOWUP`, «خانوم بهرامی» to `a_bahrami`.

## Fixes

### Critical: sprint tasks with no Target start date were invisible
- An issue only became `SHOULD_BE_STARTED` when its Target start was set and
  had passed, so anything undated fell through to `OK` and was dropped.
- Only 8 of 47 issues survived for one user, and the missing ones were absent
  rather than unmentioned — so the assistant answered "you have no tasks"
  with confidence instead of returning a partial list.
- An empty Target start means undated, not "not due yet". The check is now
  inverted: future-dated work is left alone, everything else unblocked needs
  attention. Blocked tasks are still held back.

### Critical: config entries were silently dropped at load
- `telegram_user_chat_id` was a required `int`, so a teammate registered from
  Jira before anyone had their Telegram id failed validation and vanished —
  17 of 27 entries loaded, logged as an error nobody reads.
- The field is now `Optional[int]`. Senders already skip a user without one.

### High: free text was always read as a work report
- A greeting was answered with "I did not understand how many hours you
  spent", and a question about this week's tasks was fed to the worklog
  parser. Routing by intent fixed both.

### High: project filters were ignored in answers
- «سمت پارسچت تسکی دارم؟» listed all 21 open tasks because the prompt gave
  the model no way to tell which rows were ParsChat. The three ParsChat
  project keys are now enumerated explicitly.

### High: `tqdm` missing from requirements
- Imported by `jira_data_service` and the report use cases but never
  declared, so the Docker image built and then crash-looped on
  `ModuleNotFoundError` at startup.

### Medium: daily reminder queue was unfinishable
- One user's reminder would have walked them through 187 tasks one at a time.
- Backlog issues belonging to no sprint are excluded, the remainder is capped,
  and whatever is skipped is stated plainly with a Jira link.

## DevOps

- `telegram-bot` in `docker-compose.yml` had no `env_file`, no environment and
  no network, so it could not read credentials or reach the database. It now
  joins `parschat_service_network` where `postgres_development` actually
  lives, sets `DATA_DIR`, and rotates its logs.
- The obsolete `version:` key was removed from the compose file.

## Dependencies

- `langchain` 0.3.24 → 1.3.16, `langchain-core` 0.3.56 → 1.6.0,
  `langgraph` 0.5.0 → 1.2.11, `openai` 1.76.0 → 3.3.1,
  `pydantic` 2.8.2 → 2.13.4, `python-telegram-bot` 21.4 → 22.8.
- Dropped `aiogram`: it had no imports anywhere and its pydantic ceiling
  blocked the upgrade.
- Relaxed `google-auth` to `>=2.40,<3`; `langchain-google-genai` pulls
  `google-genai>=1.65`, which the previous `~=2.35.0` cap made unresolvable.
- `--no-deps chromatrace` moved into a comment — inline `--no-deps` is not
  valid requirements syntax and made the whole file fail to install.
- LangChain 1.x removed `LLMChain` and `langchain.output_parsers`. Chains are
  now `prompt | llm | parser`, and the parts of `StructuredOutputParser` this
  repo used are reproduced in `adapters/ai_models/structured_output.py`.

## Notes

- The daily reminder still carries a `FOR TESTING: only alikaz3mi` filter and
  runs as a separate compose service that is not started by default.
- Person aliases are hardcoded in `seed_entity_aliases.py`; a new joiner is
  invisible to the assistant until that file is edited.
