# Changelog — v2.40.89

## Fixes

### Persian JQL story-lookup never found existing stories
- **Problem**: `get_story_by_release_name` used `summary = "..."` (exact JQL
  operator) which silently fails on Jira Server for Persian / Arabic text.
  Every sync run created a **new duplicate story** instead of reusing the
  existing one, causing 177 "already a Sub-task of different parent" errors.
- **Root cause**: The `=` operator in Jira Server JQL requires byte-exact
  matches and does not handle Unicode normalisation (ZWNJ, Arabic vs Persian
  Yeh/Keh).
- **Fix**: `build_jql_summary_search` now always uses `summary ~ "..."`
  (Lucene full-text) and normalises the text.  Callers post-filter with
  `summaries_match` for exact comparison.  The `exact` parameter is retained
  as a caller hint but no longer changes the JQL operator.

### Task-to-subtask conversion works via recreation fallback
- Jira Server 9.x rejects in-place `issuetype` changes (HTTP 400).  The
  existing `_recreate_as_subtask` fallback correctly migrates worklogs,
  comments, attachments, and time-tracking fields.  22 issues were
  successfully converted in production via this path.
- Added debug logging to `get_story_by_release_name` for easier future
  diagnosis.
