# Changelog — v2.40.90

## Fixes

### Sprint/Date clearing not propagating from Google Sheet to Jira

**Root cause:** Both `_create_release_story_with_subtasks` and `_process_feature`
in `SynthPMUseCase` validated ALL features through `validate_feature_for_task_creation`,
which requires sprints, dates, and assignees. When a user cleared sprints or dates
in the Google Sheet for an existing task, the feature failed this strict validation
and was silently skipped — the clearing never reached Jira.

**Fix:** Features that already have a `developer_board_issue_key` (i.e., existing
Jira tasks) now use `validate_feature_for_update` (relaxed validation that only
checks title and status). New features still go through `validate_feature_for_task_creation`
(strict: requires sprint, dates, assignees, departments).

**Files changed:**
- `jira_telegram_bot/use_cases/synth_pm_usecase.py` — Two locations updated:
  - `_create_release_story_with_subtasks`: uses relaxed validation for features with existing `developer_board_issue_key`
  - `_process_feature`: uses relaxed validation when both `jira_issue_key` and `developer_board_issue_key` exist

**Note:** `validate_feature_for_update` was already implemented in
`jira_telegram_bot/adapters/repositories/synth_pm_repository.py` — only the
use case needed the fix to call it for existing tasks.
