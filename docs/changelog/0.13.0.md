# Changelog — v0.13.0

**Date:** 2025-07-17

---

## Fixes

### Synth PM — Task-to-Subtask Conversion (Critical)
- **Problem:** Existing standalone Tasks were not being moved under their
  parent Story in Jira. The `issue.update()` approach silently failed on
  Jira Server because some instances do not support converting a standard
  issue type to Sub-task via a simple field update.
- **Solution:** Implemented a multi-try strategy in
  `JiraServerRepository.convert_to_subtask()`:
  1. **Try 1** — in-place `issue.update()` with the Sub-task type **ID**
     (not name), which works on most Jira 9.x instances.
  2. **Try 2** — raw REST `PUT /rest/api/2/issue/{key}` bypassing the
     jira-python library, for instances that restrict the library call.
  3. **Try 3 (fallback)** — recreate the issue as a proper Sub-task,
     migrate all worklogs, comments, and time-tracking fields, then
     delete the old Task. The Google Sheet reference is updated
     automatically if the issue key changes.
- **Return type** changed from `bool` to `Optional[str]` (resulting
  issue key or `None`), propagated through the entire call chain:
  `TaskManagerRepositoryInterface`, `SynthPMRepositoryInterface`,
  `SynthPMRepository`, and the use case.

### Synth PM — JQL Summary Search Accuracy
- **Problem:** `summary ~ "text"` (Lucene full-text) returned too many
  false-positive matches for Persian story/epic names, sometimes linking
  tasks to the wrong Story.
- **Solution:** Added an `exact` parameter to `build_jql_summary_search()`.
  When `exact=True`, the query uses `summary = "text"` for strict string
  comparison instead of the Lucene-based `~` operator.
- Updated all story and epic search call sites to use `exact=True`:
  - `get_story_by_release_name`
  - `_create_epic_if_not_exists` (both in `SynthPMRepository` and
    `JiraOperationsMixin`)
- Dependency searches remain fuzzy (`summary ~`) because partial name
  matching is desired there.
