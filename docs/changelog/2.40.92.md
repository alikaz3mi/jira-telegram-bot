# Changelog — v2.40.92

## Fixes

### Critical: Eliminate duplicate Jira task creation at ALL create paths
- **Root cause**: Only 2 of 7 `create_task` call sites had Jira-side duplicate
  checks.  The remaining 5 relied solely on Google Sheet write-back — if the
  write-back failed (network hiccup, quota, timeout) the next sync would blindly
  create a new issue.
- Added `_find_existing_issue()` — a reusable helper that searches Jira by
  summary (JQL `summary ~`) with `summaries_match` post-filter.  Supports
  optional `issue_type` and `parent_key` filtering for sub-task dedup.
- Applied the find-or-create guard to **every** creation path:
  - `create_jira_task_from_feature` (PM Board tasks)
  - `create_developer_board_task_from_feature` (Developer Board tasks/stories)
  - `_create_subtasks_for_assignees` (multi-assignee sub-tasks)
  - `create_release_story` (release stories)
  - `create_subtask_for_release` (release sub-tasks)

### High: Remove `PM-PCD-*` labels from developer board tasks
- Labels like `PM-PCD-123` were created using `f"PM-{feature.jira_issue_key}"`
  where `jira_issue_key` is a full key (e.g. `PCD-123`), producing confusing
  labels that the user explicitly reported should not exist.
- Removed PM-label creation from both `create_developer_board_task_from_feature`
  and `create_subtask_for_release`.
- The PM ↔ Developer Board relationship is now solely maintained through
  Jira issue links (`_link_issues`), which already existed.

### Medium: Worklog sync now resolves PM issue from links first
- `track_time_in_developer_board` now queries issue links via
  `_find_pm_board_key_from_links()` to find the PM Board issue, falling back
  to the legacy `PM-*` label lookup for backward compatibility with older tasks.
- Added `_find_pm_board_key_from_links()` helper that scans issue links for
  the PM project key.

### Critical: Rewrite `cleanup_all_duplicates.py` to be worklog-safe
- **Old behaviour**: always kept the oldest issue (lowest key number) regardless
  of whether it had any worklogs; deleted duplicates without checking or
  migrating worklogs; did not update Google Sheets.
- **New behaviour**:
  - **Keeper selection**: keeps the issue with the most worklogs; ties broken
    by total time-spent, then by key number.
  - **Worklog migration**: copies all worklogs from duplicates to the keeper
    via REST API (preserving author), with `add_worklog` fallback.
  - **Comment migration**: copies all comments before deletion.
  - **Subtask migration**: uses `convert_to_subtask` (in-place + recreate
    fallback with worklog preservation) instead of ad-hoc recreate.
  - **Safety gate**: refuses to delete any issue that still has worklogs
    after migration; reports them in `skipped_has_worklogs`.
  - **Google Sheet updates**: scans `developer_board_issue_key` column and
    rewrites rows pointing at deleted keys to the keeper key.
  - Dry-run report now shows worklog counts per issue for visibility.
